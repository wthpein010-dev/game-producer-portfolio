人 × Agent

有来源的拆解，
有边界的交付。

Agent 整理材料、拆分任务和检查一致性。人核对范围、确认疑问与验收口径，形成可继续工作的交付包。

在原项目中体验 ↗

INPUT / 保留依据

从讨论与文档中找出信息

粘贴文本或导入材料，提取决定、疑问和范围。任务可以回到来源证据，避免上下文在整理中丢失。

人工检查点

确认材料范围与关键原文，区分已经决定的内容和仍需确认的问题。

查看公开分析逻辑 ↗

STRUCTURE / 可执行任务

按职能组织开工任务

围绕策划、客户端、特效、音频、动画与测试，组织产物、依赖和验收项，把讨论变成能继续推进的工作。

人工检查点

确认分工和实现范围；任务中的负责角色不代表真实团队成员或本人的履历。

查看公开交付结构 ↗

REVIEW / 一致性检查

让未确认的问题保持可见

检查任务是否有验收依据、依赖是否完整、疑问是否解决。生成结果需要校对，不能直接视为已确认事实。

人工检查点

核对疑问与验收口径，再决定是否标记为可交付；自动检查不能替代实际验收。

查看公开检查逻辑 ↗

HANDOFF / 可检查产物

把结果交给下一步工作

导出 Markdown、JSON、CSV 或 Codex 上下文包；比较前后版本，查看需求改变影响哪些任务和验收项。

人工检查点

确认导出内容与当前版本一致，再交给团队或实现 Agent；公开示例不等于生产效率数据。

01
AGENT / 需求到交付

游戏需求开工台

如何让讨论变成能开工、能验收的任务？

+
问题

讨论散落在群聊与文档，任务、依赖和验收口径需要重新整理。关键上下文遗漏容易造成后续返工。

设计取舍

围绕“可交付任务”组织信息，保留原文证据和待确认问题；以本地分析保证示例可离线运行。

Agent / 人工协作

分析器整理材料并拆任务，质量检查器识别一致性问题。校对、范围确认和是否交付仍需要人判断。

产物与边界

可查看职能任务、验收项、版本影响并导出交付包。离线示例的结果不代表远程模型执行或实际团队效率提升。

查看证据项目与演示 ↗操作视频 ↗公开核心逻辑 ↗
02
TOOL / 多任务交互

Codex 多线程工作台

如何同时看见上下文，又能直接继续对话？

+
问题

多个任务并行时，反复进入单个对话查看状态和回复会打断操作节奏。

设计取舍

在一级界面并排保留对话、输入和状态，支持整理卡片位置；完整工作台默认打开，悬浮模式为可选功能。

Agent / 人工协作

桌面端连接本机 Codex 任务。人查看上下文、决定优先级并补充指令，任务执行状态提供反馈。

产物与边界

已有桌面产品介绍与网页交互演示。网页使用示例任务，不读取访问者的 Codex，也不会发送真实任务消息。

查看证据安全演示 ↗操作视频 ↗公开产品设计 ↗
03
GAME / 合作救援

灯塔救援队

如何用短局玩法验证观众行动与救援反馈？

+
问题

在竖屏场景中，让观众快速理解上船、选路、修理和照明，并看到操作对短局救援的影响。

设计取舍

用本地模拟观众事件验证规则，保留免费行动的有效反馈。规则事件与直播接入边界分开处理。

AI 参与 / 可检查逻辑

公开资料记录了规则状态机、模拟事件与可恢复客户端的协作构建；消息转换与有界队列的代码可检查。

产物与边界

1.4.13 的 Windows / WebGL 仍为本地模拟。SDK 无关的消息转换、队列与主线程处理已接入控制器；官方 LiveOpenSDK、真实直播间与官方 ACK 未完成验证。
