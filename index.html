04 / PERSONAL AGENT PRACTICE

AI 协作流程.

以游戏需求开工台为例。
这里展示已有能力的阅读流程。

人 × Agent

需求拆解与交付

Agent 整理材料、拆分任务和检查一致性。人核对范围、确认疑问与验收口径，形成可继续工作的交付包。

在原项目中体验 ↗

INPUT / 保留依据

整理来源

粘贴文本或导入材料，提取决定、疑问和范围。任务可以回到来源证据，避免上下文在整理中丢失。

人工检查点

确认材料范围与关键原文，区分已经决定的内容和仍需确认的问题。

查看公开分析逻辑 ↗

STRUCTURE / 可执行任务

拆分任务

围绕策划、客户端、特效、音频、动画与测试，组织产物、依赖和验收项，把讨论变成能继续推进的工作。

人工检查点

确认分工和实现范围；任务中的负责角色不代表真实团队成员或本人的履历。

查看公开交付结构 ↗

REVIEW / 一致性检查

标记待确认问题

检查任务是否有验收依据、依赖是否完整、疑问是否解决。生成结果需要校对，不能直接视为已确认事实。

人工检查点

核对疑问与验收口径，再决定是否标记为可交付；自动检查不能替代实际验收。

查看公开检查逻辑 ↗

HANDOFF / 可检查产物

交付结果

导出 Markdown、JSON、CSV 或 Codex 上下文包；比较前后版本，查看需求改变影响哪些任务和验收项。

人工检查点

确认导出内容与当前版本一致，再交给团队或实现 Agent；公开示例不等于生产效率数据。

问题

围绕“可交付任务”组织信息，保留原文证据和待确认问题；以本地分析保证示例可离线运行。

Agent / 人工协作

分析器整理材料并拆任务，质量检查器识别一致性问题。校对、范围确认和是否交付仍需要人判断。

产物与边界

可查看职能任务、验收项、版本影响并导出交付包。离线示例的结果不代表远程模型执行或实际团队效率提升。

Codex 多线程工作台

+
问题

桌面端连接本机 Codex 任务。人查看上下文、决定优先级并补充指令，任务执行状态提供反馈。

产物与边界
