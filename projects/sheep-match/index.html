设计问题

怎样让策划可调整关卡，同时避免编辑器和游戏运行结果不一致？

交付与价值

交付编辑流程、数据约束与游戏内一致性验收清单。偶数校验是基础检查，不等于保证可解；文档仍有待验收项，不宣称所有编辑器能力均已完成。

关键方案

  • 分离编辑器保存数据和运行时导出数据；明确坐标、层级、遮挡、特殊砖块与数量校验。
  • 要求手动摆放不被保存、导出或试玩随机改写；通过可点击预览、类型统计和试玩回到调整环节。

来源：麻将关卡编辑器系统策划需求文档。原图为设计流程，不是工具实机截图。

每日小物：常驻挑战与奖励承接

设计问题

怎样在主玩法之外增加每日目标，同时让挑战进度和奖励消费互不干扰？

交付与价值

把资格、余额、候选池和发奖分别定义为状态，并提供前后端分工、配置与异常验收。通关率属于设计目标，不写成实测结果。

关键方案

  • 独立两关挑战通关后获得兑换券，余额跨天累计；挑战完成与主动抽奖是两个独立操作。
  • 失败保留对应进度，换批只调整候选池；覆盖跨日、广告未知结果、断网恢复和重复回调，分享重置周期保留待核实状态。

来源：【常驻玩法】每日小物。新版规则与下方早期“小物好运局”图分开阅读。

设计问题

如何将关卡奖励接成长线目标，让重复获得的小物也有社交价值？

交付与价值

把收集动机、界面操作、资产边界与前后端验收串成完整系统；同时通过入口、浏览、装扮保存和赠送等埋点观察实际使用，不以设计目标代替留存成果。

关键方案

  • 长期收集：在关卡之外提供持续补齐的目标，以收集进度和获取方式承接回流。个性展示：用砖块小人与随身小物搭配，提供 DIY 和展示乐趣。
  • 社交互动：让符合条件的多余小物可赠送好友，为后续交换与交易预留资产规则，而非只增加库存数量。
  • 区分完整角色与按槽位佩戴的小物；浏览、试穿及批量收藏先进入草稿，服务端保存成功才改变正式状态。覆盖未保存确认、返回恢复、断网与赠送去重。

二级交易市场设计思路

设计预留 · 未确认上线

稳定分群

按用户 ID 的哈希结果将玩家稳定分为四类（A / B / C / D）。哈希用于分组，不直接决定抽奖结果；具体掉落仍由服务端按配置权重抽取。

差异化投放

为四类配置不同的小物掉落权重，形成“本组相对多、其他组相对少”的供给互补。借鉴集五福的集齐动机，让重复物成为可交换供给，缺失物形成需求。

稀缺与流通

区分群体间的相对稀缺与全市场总量稀缺；结合活跃人数、获得频次、奖励池、投放周期及回收规则调节供需，避免把四类差异做成永久绝版或无法补齐。

验证与边界

保留基础获取或保底补齐路径；设计赠送／交易资格、次数限制、库存校验与订单去重，防止多账号刷取。观察重复率、缺口、成交与收集完成率，再调整权重。

以上为本人补充的市场设计方向，不代表交易功能已开发或上线；具体概率、交易媒介、定价与回收规则尚未披露，也不作真实货币收益承诺。

设计问题

怎样先让玩家体验玩法，再在需要的入口请求授权，并处理拒绝后的去向？

将授权成功、拒绝、设置引导与原操作恢复落实为入口矩阵和验收场景。图中的阶段奖励有其他系统依赖，不据流程图宣称已经全部接入。

双节活动：从玩法规则到跨岗位验收

设计问题

怎样把活动玩法、收集结算和兑换做成团队可以分工交付的完整链路？

交付与价值

提供状态规则、异常用例、资源接入与依赖顺序。体现跨职能交付设计，不把团队美术、代码或所有配置归为个人执行。

关键方案

01 / GAMEPLAY / LOGIC

关卡玩法与胜负判定

把教学、核心挑战、配对规则与胜负结算组织为可执行的关卡流程。

  • 第一关承担教学，完成后直接进入第二关难度飞升，第二关承担核心挑战。
  • 开局生成全部砖块，相同类型的可操作砖块两两配对；坐标、层级和遮挡关系共同决定操作范围。
  • 无可配对时分别定义临时槽位、道具补救、复活和放弃的处理路径；配对完成后进入通关结算。图中为文档历史版本，与第二版入槽玩法分开阅读。
