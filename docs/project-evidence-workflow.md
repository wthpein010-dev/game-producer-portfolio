# 职业项目资料整理流程

日期：2026-10-06。来源：用户确认成语项目图文方案，并要求后续其他公司项目沿用。状态：已确认。适用范围：本仓库在线简历的职业项目资料。

## 读者与结构

面向中文 HR 和面试官。先用项目概览说明产品、任职角色和工作时间，再按系统、玩法、UI/UE 等实际材料支持的能力分区。不使用没有依据的能力评分或业绩数字。

每份证据采用“设计问题、关键方案、文档产出、资料来源”结构。区分本人已确认职责、项目文档记载、团队美术产出与本站重新整理的摘要。不能通过文件夹归属、文档元数据或修改用户名认定个人独立作者。

## 筛选与公开

1. 只读取用户指定项目目录，先列出文档与资源分类；忽略临时锁文件、运行程序和无关素材库。
2. 提取规则和操作流程，核对原文及嵌入图片；原文件保持不变。中间提取与复核记录位于仓库之外或被忽略的 artifacts 目录。
3. 不公开完整内部文档、账号、联系人、用户数据、统计报表、概率与敏感经济配置、密钥或未经审核的第三方参考素材。
4. 逐张检查精选图片。对无法可靠脱敏的图片直接弃用，改用明确标注的整理摘要；不能使用生成图冒充原图。
5. 将允许公开的精选资源复制到 assets/project-design/<project>/，记录尺寸、来源和 SHA256。文档完整原件及美术源工程不进入公开仓库。
6. 历史界面草图、示例排名、设计目标与迭代设想不能作为实际经营结果或最终上线证明。

## 排版与连接

沿用 assets/site.css 与 DESIGN.md。桌面图文对照，手机纵向阅读；竖屏图完整显示，宽图提供原图与原生 details 大图区域，并配文字要点。表格须有标题、表头和行标题。所有图片声明尺寸和有意义的替代文本。

保留公司与项目原有路由、时间轴返回位置和任职信息。新增资料接入对应项目页、所属公司入口，必要时提供独立设计摘要页；只展示该项目的资料，不误挂到同公司其他项目。

## 验证与发布

先增加针对资料结构、来源归属和公开范围的测试，再实现。运行明确指定的静态测试及受影响页面的桌面、平板、手机浏览器检查：图片加载、无重叠溢出、键盘折叠、大图滚动、原图入口和可访问性。截图报告留在 artifacts。

发布须有用户授权，并现场验证仓库权限、远端 main、工作区状态与 Pages 配置；禁止强制推送或回退其他人的修改。提交后确认 CI 与 Pages 成功，再核对线上页面及资源与本地相符。验证记录更新到项目记忆，不保存凭据。

本站不运行、构建、显示、下载或生成 ClickFlow。测试只指定本站相关文件，不使用无过滤的 Node 测试命令。
