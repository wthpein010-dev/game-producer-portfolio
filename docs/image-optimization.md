# 图片预览生成

## 生成器

原始 PNG、JPG、JPEG、WebP 保留在原路径，文件内容不变。`scripts/generate-image-variants.py` 扫描 `assets/` 下的静态位图，排除 `assets/optimized/`，生成独立 WebP 预览和 `assets/optimized/manifest.json`。SVG 不转换。

需要更新图片预览时，在仓库根目录运行：

```sh
python scripts/generate-image-variants.py
python tests/image-variants.test.py
```

生成器需要 Python 和支持 WebP 的 Pillow。本次生成使用 Python 3.7、Pillow 9.5.0、libwebp 1.3.0。重现相同字节应使用相同的 Pillow / libwebp 版本；升级编码器后应重新检查图像质量和文件大小。预览和清单一起提交。Node.js 构建、GitHub Actions 和访问网站均不需要 Python、Pillow 或新增 npm 依赖。

预览宽度为 480、960、1440、1920 像素，取不超过原图的宽度；另加入 `min(原图宽度, 1920)`，因此小图及位于两个档位之间的图片仍有原宽版本。不会放大，纵向尺寸按原比例四舍五入，缩放使用 Lanczos。每个候选只有在字节数小于原图时才写入；已经足够小的原图可以没有衍生版本，由页面继续使用原图。

PNG 全部使用无损 WebP（编码工作量 80、方法 6），避免给流程图、文字与 UI 加入有损压缩痕迹。无损模式的工作量参数只影响编码时间与体积，不丢失像素。JPEG 和原有 WebP 使用质量 92、编码方法 6；透明通道和原有 ICC 色彩配置保留。原尺寸的 PNG 预览保留原图像素，小尺寸预览以减少传输为目标，查看细节仍使用原图。

输出路径保留源图目录和扩展名，文件名包含源文件 SHA-256 的前 16 位与预览宽度，避免不同目录及同名不同格式的图片相互覆盖。源文件变化时路径变化。清单键按源路径排序，版本按宽度排序，不包含时间戳或机器绝对路径；相同输入与编码器得到相同文件字节。重新生成只清理旧清单中位于 `assets/optimized/` 内的过期衍生文件。

清单格式为：

```json
{
  "version": 1,
  "images": {
    "assets/example.png": {
      "sourceSha256": "完整的源文件 SHA-256",
      "width": 1200,
      "height": 800,
      "bytes": 240000,
      "variants": [
        {
          "src": "assets/optimized/example.png-源哈希前16位-480.webp",
          "width": 480,
          "height": 320,
          "bytes": 42000
        }
      ]
    }
  }
}
```

回归测试使用临时真实图片验证缩放边界、透明度与无损像素、四种格式和嵌套目录、原文件 SHA、重复生成、路径更新、过期文件清理，以及大于原图的预览被舍弃。

## 页面与原图

共享构建根据清单给预览图片增加 `srcset`、`sizes` 和 `data-original-src`，保留图片固有尺寸、比例、替代文本和既有原图链接。卡片、详情首图、横向图库及全宽文档使用各自的显示宽度提示；浏览器按设备宽度和像素密度选择合适文件。原尺寸折叠区继续使用原图并保持原生懒加载，灯箱在点击后请求原图；无脚本时仍可阅读预览、展开折叠和打开原图。预览请求失败时会自动恢复原文件。

构建会核对清单与原图 SHA，避免更新了截图却继续显示旧预览。生成文件名带源内容哈希，后续更新不会覆盖浏览器缓存中的旧图片。GitHub 页面与资源保持同源 HTTPS；本次没有增加外部图床、付费 CDN 或服务器公网依赖。
